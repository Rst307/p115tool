# Dashboard统计口径

数据库schema6增加每日指标聚合表。累计和每日计数同一事务写入，进程重启不会清零。旧库升级保留累计值，但不根据旧总数猜造历史每日值。

## 每日周期

`statistics_utc_offset` 是固定UTC偏移分钟数，默认480（UTC+08:00），允许-720至840。页面显示日期和偏移；固定偏移不是自动夏令时地区时区。修改偏移会使用独立的每日统计分桶，不把不同日界线的数据混合；累计不变。

播放结果及耗时计入该请求开始时的统计日，即使解析跨午夜也不会出现请求数和结果数分属两日。

## 数量和容量

- 今日STRM写入：成功完成原子写入的次数，包含重生成，不是新增媒体数。
- 今日分享创建：SDK成功返回且分享标识已记录的创建操作次数；单文件与电影/季组各计一个分享。创建超时后的未知远端结果不猜计，接入已有分享也不计为新创建。
- 源删除确认字节：删除成功或显式对账确认缺失后，首次将该媒体记录为已删除的字节数。身份标记和统计同事务提交，重试对账不重复累计。对账确认时间不是推断的实际删除时间。
- **源删除确认字节不代表实际容量到账**：源移入回收站后，账户实际配额是否释放及何时到账仍由115决定。页面不会把此值称为已验证的空闲容量。
- STRM记录：数据库有strm_path的媒体数，不是每次页面请求都递归检查磁盘的存在数。
- 分享数：已有分享对象的不同share_code数量。容量是各存储类型的逻辑媒体字节；缓存占用独立列出，不能把两者相加当账户实际占用。

## 302统计

有效媒体请求：已找到媒体且通过token/UA校验的解析请求，包含GET和HEAD；不是独立观看人数或播放会话数。无效token及框架拒绝的请求不计。

成功率 = （成功获取直链次数 + 有效直链缓存命中次数）/ 有效媒体请求次数。缓存命中本身是成功；错误率 = 捕获到的解析错误 / 请求次数。进程中断或尚未完成的请求可能没有结果，不能据此推断成功。

缓存命中率 = 有效直链缓存命中 / 请求次数。

平均解析秒数 = 非缓存成功的累计耗时 / 非缓存成功次数，包含本服务获取并发门/锁及降级耗时，不包括视频传输或客户端播放体验。缓存命中不作为零秒样本稀释平均值。没有相应样本显示“暂无”，不伪造100%成功率或零耗时。

## 证据与边界

`test_metrics.py`使用真实SQLite/插件页面结构及可控网盘客户端，覆盖日界线、跨午夜结果、重启、时区隔离、旧库升级、缓存命中、失败分母、单分享和删除对账幂等。页面仅完成宿主组件结构测试，真实MoviePilot渲染、真实账户实际容量和真实播放性能仍待联调。
