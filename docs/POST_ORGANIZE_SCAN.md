# 整理后统一扫描（0.1.6）

流程为：MoviePilot正常整理 → 每天统一扫描整理后115目录 → 建立虚拟媒体索引 → 分别执行虚拟分享、STRM后台任务。

1. 在MoviePilot中配置正常整理任务、115存储和媒体库目录。
2. 在插件“STRM”配置中选择MoviePilot整理后的目录，目录prefix应对应该115目录真实路径。不要选择下载暂存目录。
3. 在“整理后扫描”中设置每天扫描时间，格式为HH:MM，默认03:00；时区使用“每日统计UTC偏移”，默认北京时间UTC+08:00。旧scan_interval及auto_organize_enabled配置保留兼容读取，但不控制新扫描流程。
4. “定时扫描后自动创建虚拟分享”和“定时扫描后自动生成STRM”独立控制。虚拟分享还须启用分享存储；显式SHARE文件规则也可提交自动分享任务。虚拟分享仍按file/movie/season/auto策略聚合。
5. 插件媒体页提供“立即扫描整理后目录”“开始创建虚拟分享”“开始生成STRM”。手动扫描仅更新索引；等待扫描任务完成后，再分别点击所需输出按钮。批量按钮使用最近一次成功扫描的媒体；修改扫描目录后须重新扫描。手动分享遵循显式NORMAL排除规则，但不要求开启自动分享。

整理事件只保存目标识别、类型、季、类别等元数据，不立即入库、创建分享或生成STRM。扫描以远端枚举到的身份和路径为准，并应用已记录的MoviePilot分类信息。漏收事件的文件仍可扫描入库，缺少识别身份时退回文件级分享。

完整目录扫描成功后才公布批处理媒体快照；枚举失败或文件导入／缺失对账失败时不提交自动输出任务。分享和STRM各自有独立任务状态，分享失败不阻止队列执行另一个STRM任务；任务详情和日志用于查看失败检查点。

新批处理及手动分享阶段始终保留源文件，且不生成STRM。已有STRM在生成任务中可更新。历史显式删除接口继续要求分享、Range、STRM等验证；未生成STRM不能绕过删除门禁。分享创建结果不明时，新一轮手动任务也不会盲目重建。健康检查仅修复已有STRM，不替尚未执行STRM阶段的媒体创建文件。

升级重载时取消旧版本尚未执行的自动整理委托及整理事件归档任务，避免旧任务继续触发旧流程；已开始或结果不明的任务保留检查点及只读对账入口。

本轮使用离线客户端验证流程与安全门，没有调用真实媒体删除。真实MoviePilot定时触发、115分享及Emby播放仍需部署验收。
