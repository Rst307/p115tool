# 扫描、源缺失对账与STRM清理

## 自动扫描

`source_cids` 配置数字CID或 `{"cid":"123","prefix":"/电影"}`。扫描递归枚举目录，排除配置的缓存根目录；以远端file_id保持媒体身份和播放token，移动文件会更新虚拟路径及STRM。

数据库schema5增加 `scan_members`（扫描根/媒体身份）和 `missing_sources`（独立确认的源缺失证据）。记录不是仅凭虚拟路径前缀推断。子目录消失后，历史成员仍可对账；取消监控某根目录不会触发该目录成员的缺失处理。

必须所有配置根目录枚举成功后才执行缺失对账。某页/某目录失败、目录循环或超限会终止本次对账；此前成功导入的新增媒体可能已保留，但不会据不完整列表删除STRM或归档源文件。

列表未出现的文件不是“已删除”：先检查认证，再独立查询file_id。明确不存在才记录缺失；超时、未知响应、内容身份变化都保留STRM。文件仍存在但移出监控根时记为OUTSIDE，不标为缺失。目录扫描与外部移动不具备远端事务一致性，因此独立查询是必要的第二道门槛。

## 保留与清理

- 默认 `clean_missing_strm=false`：普通源明确缺失时标记BROKEN，保留STRM、媒体记录、token和虚拟路径。
- 有分享或缓存对象、已虚拟化的媒体：保留STRM及归档检查点，不把个人盘源缺失等同于全部播放后端失效。
- 未完成整理计划、归档进行中或FAILED_DELETE等不确定写状态：不覆盖检查点，先用专属恢复流程。
- 开启 `clean_missing_strm=true`：只清理本次确认缺失、没有分享/缓存替代的普通STRM。路径必须位于输出根、数据库归属匹配、内容等于该媒体稳定播放地址；手工编辑的文件不会删除。
- 清理只删除本地STRM，不删除远端文件、不清空回收站、不删除数据库身份。重新出现同一file_id且内容身份不变时，扫描可恢复相同token的STRM。

## 手动清理接口

`POST /strm/cleanup`（相对插件API前缀），使用管理API Key。

```json
{"media_id": 1}
```

`{}` 检查全部已记录的缺失来源。此显式操作不要求自动清理开关开启；仍必须重新认证和查询当前源，不能凭陈旧证据清理。响应示例：

```json
{"removed": [1], "inconclusive": []}
```

不存在缺失证据、源已恢复、校验失败或存在替代后端时不删除。鉴权失败返回401；认证不可用或远端查询不确定时保留文件。

## 验证边界

`test_scanner.py`覆盖完整/失败扫描、子目录消失及重启、跨根/移出监控、认证/查询故障、内容变化、普通源恢复、分享/缓存保护、未完成整理、已编辑STRM、自动清理开关和手动接口鉴权。远端由可控客户端模拟；115真实目录分页、权限响应及跨客户端并发行为仍需授权测试账号验证。没有使用真实媒体做删除实验。
