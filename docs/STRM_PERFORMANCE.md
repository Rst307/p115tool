# 大批量STRM生成优化

2026-10-02，离线模拟115列表，不连接真实115、不操作真实媒体。

## 问题与改动

每个文件的存储排除、映射注册、输出归属及进度查询此前都新建SQLite连接。120个已有文件重复生成会开关965次连接，并逐文件提交122次进度。

- Service在现有互斥锁内复用数据库连接与预编译语句；每次写入仍独立提交，异常回滚，停止并等待后台任务结束后关闭连接。
- 元数据、输出指纹和STRM路径未变化时不重复写入数据库；文件身份核实仍逐文件执行，内容变化和手动编辑继续拦截。
- 生成进度最多每秒提交一次，启动及最终状态必定提交；替换、迁移、远程写操作检查点不受进度节流影响。
- 为当前和归档临时目录、临时文件的排除查询建立索引，避免每个文件重复全表扫描。排除信息实时读取，保留播放中新建副本的隔离。
- 已有STRM只读一次进行内容比较；旧位置排查跳过本轮已验证的当前输出，仍核实候选旧副本身份及归属后迁移。

## 模拟结果

同一Windows开发环境，120个分类视频，首次与重复生成：

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首次生成 | 6.68秒 | 3.97秒 |
| 重复生成 | 3.16秒 | 0.96秒 |
| 重复生成数据库连接 | 965次 | 1次 |
| 重复生成进度提交 | 122次 | 2次 |

此为本地模拟结果，不是现场115测速。实际耗时仍取决于目录数、115分页与限频、宿主识别、输出盘和挂载延迟。未增加115并发请求，未取消原子输出或fsync。

## 回归检查

`tests/test_strm_performance.py`使用真实Service生成路径，覆盖120个文件重复生成的连接及进度数量、映射与文件时间戳保留、未变化记录零更新、跨线程提交及异常回滚、停止阶段最终状态持久化，以及2000份副本记录的索引使用和实时目录排除。

全量221项中219项首次通过；两项新增测试夹具的SQL占位符及连接关闭错误修正后，仅重跑性能模块3项全部通过。已有播放、清理、永久删除、地址替换检查点、分类与旧STRM迁移测试通过。
