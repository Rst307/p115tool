# 当前插件范围与验证

更新时间：2026-10-01（Asia/Shanghai），版本0.2.7。

用户本轮明确缩减目标，当前范围（已按本轮要求增加手动MoviePilot整理入口）：

- 独立STRM生成：递归遍历配置的所有115个人网盘文件夹，过滤影视扩展名，直接输出到本地目录；不要求旧成功扫描快照。
- 分类：已有电影／电视剧／动漫目录沿用类型及类别；选中类别子目录仍保留分类；其他资源使用MoviePilot MediaChain识别，无法识别则使用未识别／未分类目录。
- 302：普通源稳定token映射，GET／HEAD、播放器UA透传，实时取直链、不代理视频、不向播放器发送Cookie。
- 原生配置页：源目录选择／手工ID与完整路径、输出目录、播放地址、可选每日生成；详情页一键生成、数量及固定脱敏失败原因。

新增“一键整理”入口仅委托宿主，不执行插件整理、不恢复整理事件或整理数据库。已删除当前插件的分享、转存、缓存、删除、回收站、健康修复、整理／整理事件记录、旧持久队列、额外管理API及旧独立网页。115 SDK只通过P115ClientManager调用；当前Manager只有目录、详情和普通直链读取能力。

升级使用独立strm_files／strm_state表。旧media.sqlite3保留，不执行或迁移旧任务；仅导入NORMAL且未删源的映射并保留token。分享／缓存不导入，不再提供旧虚拟资源播放。默认不启动定时任务，需用户开启新的每日生成开关。内容不同的现存STRM拒绝覆盖。0.2.4增加受保护的本地STRM旧位置迁移，网盘源不删除。

## 0.2.6 修改播放地址后更新旧STRM

用户报告Hills转圈及无兼容流，确认MoviePilot与Emby分别在两个Docker容器，MoviePilot页面为192.168.0.2:3000，但STRM仍使用127.0.0.1:8000。离线复现旧生成器修改public_url后报OUTPUT_CONFLICT，原文件保持回环地址；新增地址回归修复前2项失败，明确验证内容而非仅接口返回302。

新增本地输出内容指纹与地址替换检查点。验证源身份后，对同文件ID且指纹一致的输出更新地址，token保留；旧0.2.5输出仅在记录路径匹配、精确token和固定默认回环端点匹配时兼容采用。手工编辑、不同token、无记录路径、根外与符号链接不采用。旧文件字节复查后提交PENDING，再原子替换；失败标记UNKNOWN，不重试不明结果。指纹及检查点不存播放URL，不进入状态／错误响应。兼容旧Windows CRLF输出，新输出固定LF。配置页提示回环地址在不同Docker容器内的含义，以及保存后重新生成的步骤。

真实部署尚未验证Emby访问MoviePilot及115跳转，不能将离线地址修复视为Hills播放验收。未访问真实账号或操作真实媒体。

## 0.2.2 一键整理

页面勾选已配置115源文件夹，一键调用MoviePilot TransferChain.manual_transfer，target_storage=u115、transfer_type=copy、background=True、force=False、sync_extra_files=True。宿主递归识别、分类、命名、复制、附加文件处理；目标由MoviePilot媒体库规则决定，插件不监听或记录结果。整理完成后，配置整理目标为源目录并单独生成STRM。

先通过StorageChain.get_file_item只读核对目录存储、目录类型、CID、完整路径，任一不匹配则整批不提交；非根CID配根路径不会误整理全盘。重叠目录只提交祖先，浏览器避免连点，STRM运行时不接收整理。宿主异常仅返回固定UNKNOWN并停止剩余目录，不自动重试，不透传宿主异常／错误消息。

核对宿主v2.15.6接口，证据：[TransferChain](https://github.com/jxxghp/MoviePilot/blob/v2.15.6/app/chain/transfer.py)、[StorageChain](https://github.com/jxxghp/MoviePilot/blob/v2.15.6/app/chain/storage.py)。本轮为跨模块及宿主接口变更，后端全量33项通过（2.116秒），包括9项新宿主委托／目录身份／重叠／未知结果／管理员鉴权回归；前端5项通过，Vue联邦重新构建并同步，0.2.2目录安装包和仓库包生成通过。真实宿主整理仍待部署验证，未操作真实媒体。
