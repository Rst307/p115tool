## 一、交付目标与当前基线

交付物是 **MoviePilot 原生插件「115 工具箱」**，不是独立网站。配置、媒体管理、分享管理、任务与恢复操作应在 MoviePilot 内完成；核心播放仍由插件 API 返回 302。

范围保持原始42节方案，以 STATUS.md 为逐项审计依据。目前有统一媒体数据库、STRM、三后端播放、分享归档、缓存、整理、任务与恢复的基础实现，以及部分原生页面操作。244项离线测试通过，但真实 MoviePilot／115／Emby 链路尚未验收。

不按测试数量推算完成百分比，不重新开发已经有证据的核心模块；下面逐项补齐缺口。

## 二、执行顺序

主线：**原生插件安装与宿主契约 → 原生管理界面 → 恢复与整理补齐 → 回收站策略 → 真实全链路验收 → 发布**。

真实宿主渲染验证从第一阶段开始，不留到最后。无删除的115测试可与界面开发并行；真实删除与永久清理由独立授权门控制。

### 阶段1：固定 MoviePilot 原生交付与安装（P0）

开发工作：

- 确认目标 MoviePilot 后端、前端版本及插件目录／安装契约，记录兼容矩阵。
- 检查插件入口、配置保存、初始化／停止／重载、周期任务及 API 注册；补充重载竞态和资源关闭测试。
- 核对原生表单数字、布尔、规则／模板字段的实际序列化；错误配置不能损坏正在运行的数据。
- 整理插件目录部署包、依赖声明及版本信息；按目标宿主要求补齐仓库安装元数据。Python wheel 不代替 MoviePilot 安装验收。
- 明确独立服务只是辅助测试工具，不作为默认入口或用户必须启动的组件。

交付与验收：

- MoviePilot 能加载、启停、保存并重新读取配置；重启后媒体、任务和播放 token 保持。
- 在真实宿主打开插件配置与详情页，无需启动8765演示服务。
- 未登录、普通用户、停用账户不能执行管理动作；页面与错误不泄漏凭据。

依赖：需要目标 MoviePilot 版本及可用测试实例；在此之前可完成打包和离线契约测试，但不能标记真实兼容通过。

### 阶段2：补齐 MoviePilot 原生管理界面（P0）

开发工作：

- Dashboard：账号观察时间／过期标记、NORMAL／SHARE／CACHE容量、异常、每日指标及任务进度。
- 媒体与 STRM：自由搜索、目录／状态筛选、分页、详情、单个／全库生成、扫描与失效STRM处理。
- 分享：单文件／电影／季分组查看、成员及验证结果、分享导入／未知创建结果接入、保留源归档与修复入口。
- 缓存：占用、最后访问、过期时间、播放租约、恢复进度、受保护删除与结果对账。
- 任务：状态、检查点、脱敏失败原因、取消、安全重试、只读对账及明确授权的续做。
- 设置：九组配置完整可编辑；规则与模板提供校验提示，避免只能手写难以验证的JSON。
- 源删除与其他破坏操作增加独立二次确认；普通扫描／归档不能隐式继承自动删除授权。

实现约束：

- 先核对宿主输入绑定、表单提交及刷新契约，不能假设 PageRender 固定 params 能读取动态输入。
- 如目标宿主原生组件无法支持复杂输入，则采用宿主支持的插件 Vue／模块联邦页面；仍安装、展示在 MoviePilot 内，不另起管理网站。
- 管理接口持续验证管理员身份；不能只靠隐藏按钮或页面 nonce 授权。

交付与验收：

- 常用管理流程在插件内闭环，不跳转独立网页、不要求输入额外管理API Key。
- 真实宿主完成搜索→详情→提交任务→查看进度／结果；失败与恢复操作有明确提示。
- 已播放缓存、身份不明文件、未验证分享不能通过界面绕过后端安全门。

### 阶段3：补齐恢复、整理与自动化边界（P1）

开发工作：

- 审计归档、分组、分享修复、目录创建、移动／重命名、转存、删除的完整状态转换与恢复入口。
- 对每类远端写区分「可安全重试」「只能对账」「需人工接入／授权续做」；未知结果绝不通用重发。
- 配置更新、任务取消、进程中断、部分成功后重启，都必须保留检查点和原授权范围。
- 补齐跨季／非连续多集、缺少可靠媒体识别等整理边界：先输出明确拒绝与人工确认流程，再实现可无歧义的规划；不猜集号或错误自动移动。
- 核对 MoviePilot 真实下载／整理事件字段、重复事件、延迟可见性及扫描补偿，避免重复入库／归档。
- 补齐302页面的UA策略、只读失败重试边界、超时／并发配置及对应测试；远端写不套用播放重试。

交付与验收：

- 每种不确定远端操作都有可见状态、检查点、对账与人工处理说明，不出现“点重试就再写一次”。
- 重启、重复事件、配置变化不导致重复删除／重复转存或播放 token 改变。
- 未识别或存在歧义的合集不自动整理；支持范围及人工处理方式明确记录。

### 阶段4：实现完整回收站策略（P1，高风险）

已有基础：schema7删除请求账本；它不是回收站条目所有权证明。

开发工作：

- 通过 P115ClientManager 增加回收站列表与分页解析，核对固定SDK版本及真实响应字段。
- 建立原删除意图与回收站条目ID的可靠映射；同名／同大小不算确证，历史条目不自动认领。
- 实现三个配置选项：仅删除至回收站（默认）、N天后清理、自动清空。
- N天策略只清理确证归属且达到期限的条目；未知身份、分页失败、时间证据不足时跳过并告警。
- 自动清空作为账户级不可逆功能单独授权，明确会影响非插件条目，绝不随源删除开关启用。
- 永久清理先落持久检查点；超时／重启先只读对账，不盲目重复。定向清理拒绝空条目批次，账户清空走独立明确路径。
- 完成原生配置、回收站列表／归属标识／计划预览、授权确认与任务结果页面。

交付与验收：

- 离线覆盖三种策略、身份冲突、分页失败、时间边界、凭据错误、空批次与未知结果重启。
- 实盘先只读确认条目身份，再以明确授权的可丢弃文件验证定向永久清理。
- 若真实API无法提供可信映射，N天清理保持不可执行并列为未完成，不能降低匹配标准凑数。
- 账户级自动清空不能在用户真实混合回收站中作为默认验收步骤；必须有单独授权和可控测试范围。

### 阶段5：真实 MoviePilot＋115＋Emby 验收（P0发布门）

按风险递增执行，不一次性开启全部自动化：

1. **只读／不删源**：登录与容量响应、普通文件扫描、STRM、普通302、Emby播放与拖动；核对UA及反向代理日志。
2. **保留源分享**：创建、目录读取、身份校验、Range、单文件／分组播放；验证失败不删源。
3. **可丢弃源删除**：独立授权后删除测试源；立即及重启后验证分享播放和稳定STRM，并记录回收站条目。若分享失效，阻止开放自动删源。
4. **缓存降级**：可控故障触发重扫／转存，验证异步可见性、普通直链、容量清理、LRU和播放租约。
5. **事件自动化**：真实MoviePilot事件→识别／整理→STRM→分享策略→Emby播放；重复事件及中途重启不重复写。
6. **Emby事件**：Start／Progress／Stop真实负载、挂载映射与多会话；Stop不能直接删缓存。
7. **健康与恢复**：失效分享、保留源／缓存修复、任务中断、只读对账及人工续做。
8. **回收站**：完成阶段4的独立高风险验收，不与普通播放验收混为一项。

交付与验收：

- 每条用例记录版本、条件、预期、实际结果及脱敏证据；失败回到对应开发阶段修复。
- 客户端获取302后直接访问115 CDN，插件不代理视频、不转发Cookie。
- 分享删除后持久性是必须通过的实盘条件，不把“创建成功”当作已证明安全。

### 阶段6：发布与完整目标核对（P1）

- 执行全量回归、安装／升级／回滚、数据库迁移及重启测试。
- 检查日志、错误、页面、反向代理配置示例中的Cookie、分享密码、播放token与直链泄漏风险。
- 完成安装包、配置说明、备份与恢复、已知兼容范围、危险操作说明及故障处理文档。
- 按原始42节逐条填写：开发证据、离线验证、真实验收、剩余限制，不以功能按钮存在替代完成。
- 只有必需功能与真实链路通过后，才声明完整目标完成；未通过项继续列为剩余工作。
