# 旧整理检查点与扫描恢复（0.1.11）

`scan_import · FAILED_ORGANIZE_PENDING` 表示该文件在本地 `organize_plans` 中仍有未完成记录；扫描未生成完整成功快照，后续STRM批处理因此报 `FAILED_SCAN_REQUIRED`。

此记录与详情中的“MoviePilot整理：FAILED”不同。后者是宿主委托结果，不足以证明旧移动／重命名计划已经完成，也不应作为清除旧检查点的依据。必须用媒体ID关联失败文件与详情。0.1.11扫描失败日志新增媒体ID（已存在媒体时），避免查看另一个文件的详情。

旧版扫描在读取已完成的远端目标后仍直接拒绝入库。0.1.11只对以下情况自动做本地只读对账：

- 当前扫描枚举结果处于旧计划的目标目录及目标名称。
- 文件ID、非目录属性、SHA1及大小与计划、媒体及普通源记录一致，SHA1必须为40位非空哈希。
- 再通过统一客户端读取详情，文件ID、名称、目录、SHA1、大小及提取码与枚举一致。
- 记录仍为普通源且未删除，不存在分享、缓存、删除请求及危险阶段保护。

通过后在同一数据库事务更新本地文件名、虚拟路径、目录及提取码，将旧计划标记DONE；保留计划全部历史字段、媒体ID和播放token。虚拟路径采用当前完整扫描的路径。扫描不移动、不重命名、不删除远端文件，也不生成STRM；完整扫描成功后点击“开始生成STRM”。

未完成移动／重命名的文件继续显示 `FAILED_ORGANIZE_PENDING`，请按媒体ID打开详情查看整理检查点并执行“整理只读对账”；剩余整理需在MoviePilot完成。原位置仍存在不代表未知提交已经失败，扫描不会自动取消其计划。身份变化显示 `FAILED_ORGANIZE_IDENTITY`；远端详情查询失败显示 `FAILED_ORGANIZE_LOOKUP`，均保留检查点，不记录异常原文或敏感信息。

离线回归覆盖目标已完成时恢复索引与后续STRM、部分结果保护、未知结果重启保留、详情与枚举冲突、已删除源及分享源保护、内容变化及异常隐私。用户实例仍需升级后重新扫描验证；提供的Hamilton ISO详情只有MoviePilot失败记录，没有旧整理检查点信息，不能认定其就是扫描失败对象。完整42节目标仍未完成。
