# STRM批量生成失败排查（0.1.10）

`generate_batch` 的 `NEEDS_ATTENTION` 表示本次批处理未完成，不等于115连接失败。0.1.9及更早版本将原因折叠为通用错误，仅凭任务开始／结束日志无法判断根因。

0.1.10任务详情和宿主日志输出固定脱敏原因码：

| 原因码 | 处理方式 |
| --- | --- |
| FAILED_SCAN_REQUIRED | 没有完整成功扫描快照。先点击“立即扫描整理后目录”，确认扫描错误数为0，再点击“开始生成STRM”。扫描任一文件入库失败也会使快照失效，先处理扫描错误。 |
| FAILED_SCAN_ROOTS_CHANGED | 目录配置与上次成功扫描不一致，重新扫描成功后再生成。 |
| FAILED_OUTPUT_PARTIAL | 部分输出失败，按本次日志媒体ID查看下列逐文件原因；已经写入成功的STRM保留。 |
| FAILED_STRM_PERMISSION | 检查MoviePilot进程对配置STRM目录及子目录的写入、替换权限和容器挂载。 |
| FAILED_STRM_CONFLICT | 目标文件已被编辑或归属另一个媒体对象；保留文件并核对归属，不自动覆盖。 |
| FAILED_STRM_IO | 检查磁盘空间、挂载及目标目录结构，错误原文和路径不会输出。 |
| FAILED_STRM_ENCODING | 目标已有文件不能按UTF-8读取，先核对是否为用户文件。 |
| FAILED_STRM_SAFETY | 本地路径或其他安全校验未通过，检查配置与媒体记录，不绕过保护。 |
| FAILED_STRM_INTERNAL | 其他本地生成异常，提供版本号、媒体ID和固定原因码以继续排查。 |

日志不会包含Cookie、分享密码、播放token、直链或异常原文。输出仍使用最近一次完整成功扫描的媒体快照；失败扫描不会被跳过。确认原因并处理后，可重新点击“开始生成STRM”提交新任务；这不重试分享、转存或删除。

离线回归覆盖无快照失败及成功扫描后的恢复、目录变化、已编辑文件保护、写入权限异常及隐私。用户任务#21仅提供通用日志，实机原因尚未确认；这些修复补齐可诊断性，不代表已经验证用户实例恢复。
